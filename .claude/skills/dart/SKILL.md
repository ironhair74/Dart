# DART 공시 분석

DART 공시로 두 가지 일을 한다. 먼저 요청이 어느 쪽인지 고른다.

- **실적 리포트.** "○○ 실적 리포트", "○○ 3분기 실적 어때"처럼 한 회사의 분기 실적을 정리해 달라는 요청이다. 아래 Step 0~7로 HTML 리포트를 만든다. 6개 섹션(핵심 실적, 성장 기여도, 사업별 매출, 애널리스트 시각, 뉴스, 13인 투자자 시각)과 맨 위 결론 한 줄과 맨 위 결론 2문장과 맨 아래 전문가 평가(RED·SILVER·GOLD, 10점 만점)가 들어간다. 15~25분 걸린다(전문가 평가 뒤 고침 포함).
- **빠른 조회.** "최대주주 지분이 늘었어?", "부채비율 얼마야", "등기임원 명단"처럼 공시 숫자 몇 개를 묻는 요청이다. 리포트를 만들지 않고 바로 아래 "빠른 조회" 절차로 1분 안에 답한다.

애매하면("카카오 요즘 어때") 빠른 조회로 핵심 숫자를 먼저 답하고, 리포트로 만들지 한 줄로 묻는다.

## 빠른 조회

같은 스킬 안에 DART 도구 16개가 있다(`assets/mcp_server.py`). 회사 이름 해석, 최근 보고서 고르기, 연결이 없을 때 별도로 바꾸기, 원문 링크 붙이기를 도구가 한다. 그래서 **DART API를 부르는 코드를 새로 짜지 않는다.**

- `share_top_holders` 같은 이름의 MCP 도구가 보이면(서버 이름 `dart`) 그것을 부른다.
- 보이지 않으면 같은 도구를 명령줄로 부른다. 결과는 같다.
  ```bash
  python3 ~/.claude/skills/dart/assets/mcp_server.py --call share_top_holders '{"corp": "카카오"}'
  python3 ~/.claude/skills/dart/assets/mcp_server.py --list        # 도구와 입력 목록
  python3 ~/.claude/skills/dart/assets/mcp_server.py --help fin_ratios   # 도구 하나의 입력 상세
  ```

| 묻는 것 | 도구 | 메모 |
|---|---|---|
| 어떤 회사인지, 대표자·업종·결산월 | `corp_profile` | 이름이 애매하면 `corp_resolve` |
| 최대주주·특수관계인 지분, 그 변화 | `share_top_holders` | 기초·기말이 한 표에 있다. 합계 행은 `relate`가 "합계(…)" |
| 5% 이상 주주의 보고 | `share_block_reports` | 최근 접수순 |
| 임원·주요주주 지분 매매 | `share_insider_reports` | 최근 접수순 |
| 등기임원, 임기, 경력 | `people_executives` | 등기 여부는 `rgist_exctv_at`, 임기 정렬은 `tenure_end_on_iso` |
| 직원 수, 평균 급여, 근속연수 | `people_employees` | 급여는 기간 누적이다(반기면 6개월치). 연봉을 물으면 사업보고서(`year`만)로. 1분기 보고서에는 급여가 빠진 경우가 많다 |
| 매출·영업이익·순이익·자산 | `fin_key_accounts` | 계정 몇 개면 이것, 전체 표는 `fin_statements` |
| ROE·부채비율·유동비율·증가율 | `fin_ratios` | 2023년 3분기 보고서부터. 분기·반기 값은 연초부터 누적이고 연환산하지 않았다. 기준(연결·별도)은 `meta.basis` |
| 배당 | `fin_dividends` | |
| 발행·유통 주식 수, 자기주식 | `share_outstanding`, `share_treasury` | |
| 증자·감자 이력 | `share_capital_changes` | |
| 최근 공시, 특정 기간 공시 | `filing_search` | 이 표에 없는 공시(주요사항보고서 등)도 여기서 원문 링크를 찾는다 |

기간을 말하지 않았으면 `year`를 비운다. 도구가 가장 최근 정기보고서를 골라 `meta.period_source`에 적는다. "작년"은 `year`만 주면 사업보고서(FY)다. "올해 상반기"는 `{"year": "<올해>", "period": "H1"}`이다.

**답하는 법.** 숫자마다 근거를 붙인다.

- 어떤 보고서의 언제 기준인지(`meta.period_source`, `stlm_dt`), 재무 숫자면 연결인지 별도인지(`meta.basis`)를 밝힌다. 연결이 없어 별도로 답했으면 그렇다고 말한다.
- 응답의 `source_url`(또는 행의 `url`) DART 원문 링크를 붙인다.
- 숫자는 응답 값에서 온다. 비율은 소수 첫째 자리로 줄여 쓰고(83.588 → 83.6%), 구성 숫자를 함께 적는다(부채 12.6조, 자본 15.1조). 비율을 직접 계산했으면 계산식을 밝히고, `fin_ratios`에 같은 지표가 있으면 대조한다.
- 보고서 이름을 독자 말로 풀어 쓴다("반기보고서 = 6월 말 기준", "[기재정정]은 정정본"). 분기·반기 비율(ROE·이익률)은 "연초부터 누적, 연환산 아님"을 답에 적는다.
- 비율의 구성 숫자는 `fin_key_accounts`로 가져온다. 방향을 한 줄 붙인다(같은 응답의 증가율 행은 전기말·전년 같은 기간 대비라고 밝히거나, 직전 사업보고서 값과 견준다). 해석은 구성 비교(부채 < 자본)로만 하고, 업종 평균처럼 원천에 없는 기준은 대지 않는다.
- 응답이 `error`와 `candidates`를 주면 후보를 보여 주고 고르게 한다. `note`가 "데이터가 없습니다"면 그 기간에 공시가 없다는 뜻이니 기간을 바꿔 한 번 더 보거나 그대로 알린다.
- `truncated`가 있으면 일부만 온 것이다. `hint`대로 좁혀 다시 부른다.
- 짧게 답한다. 숫자와 근거가 먼저고, 해석은 한두 줄이다. 실적 흐름 전체가 궁금해 보이면 "리포트로 만들까요?"를 덧붙인다.

## 실적 리포트

### 이 스킬이 일하는 방식

**너는 조사와 판단을 하고, 숫자와 조립은 스크립트가 한다.** 숫자(실적·증감률·이익률·주가·목표가 평균)는 옮겨 적지 않는다. 조사와 서술은 서브에이전트가 **조각 파일**에 남기고, `verify_report.py`가 실적·주가·목표가와 서술에 단위와 함께 쓴 숫자를 원천과 대조해 통과해야만 HTML이 나온다(뉴스 본문 숫자는 V1이 기사와 대조한다).

**사용자에게 하는 말.** 기다리는 동안 말없이 있지 않는다.

| 때 | 말 |
|---|---|
| Step 2 뒤 | 기간과 걸리는 시간. "2Q26(반기보고서, 6월 말) 기준으로 만듭니다. 15~25분 걸립니다" |
| Step 4 시작 | "뉴스·증권사·부문 매출을 조사하고 출처를 확인하는 중입니다" |
| C 시작 | "출처 확인이 끝나 결론과 투자자 평가를 쓰는 중입니다" |
| R 고침 | "전문가 평가가 N점이라 지적 M건을 반영해 한 번 다듬습니다. 5~10분 더 걸립니다" |
| 게이트 FAIL | "숫자 N건이 원천과 달라 고쳐서 다시 확인합니다(2/3회차)" |
| BLOCKED | 플래그 이름 없이 "이 숫자 N개를 확인하지 못했습니다. ① 값을 알려 주시면 반영 ② 경고를 달고 발행 ③ 중단" |
| 전달 | 아래 예문 형식 |

전달 예문: "카카오 2Q26 리포트입니다: output/카카오_20261029_01.html / 결론: <HEADLINE 그대로> / 숫자 74개를 DART·KRX 원천과 대조했습니다. 뉴스 5건·증권사 5곳 확인, 부문 매출은 IR 기준입니다. 전문가 평가 최저 9.0(남은 한계: <최저점 역할의 limit. 동점이면 RED·SILVER·GOLD 순>). PDF가 필요하면 말씀하세요."

### 한눈에 보는 흐름

| 단계 | 하는 일 | 명령 |
|---|---|---|
| 0 | 준비: 작업 폴더·API 키 | |
| 1 | 종목 확정 | `corp_registry.py "<이름>" --verify` |
| 2 | 기간 정하기 | `assemble_report.py period --corp-code <c>` |
| 3 | 사실 뽑기 | `assemble_report.py facts --corp-code <c> <args>` |
| 4 | 조사와 출처 검증 → 조각 파일 | A1·A2a·A2b → V1·V2a·V2b, 그 뒤 B(V1 뒤)·C(V 셋 뒤) |
| 5 | data.json 조립과 전문가 평가 | `build` → R → (9.5 미만이면 B·C 한 번 고침) → `build` |
| 6 | 숫자 검증 게이트 | `verify_report.py <data.json>` |
| 7 | HTML 빌드·전달 | `build_report.py <data.json>` |

명령은 모두 `python3 ~/.claude/skills/dart/assets/<스크립트>`로 부른다. `~/.claude/skills/dart`는 이 SKILL.md가 있는 폴더다(플러그인으로 설치했으면 그 폴더 경로로 바꿔 쓴다). 스크립트 소스는 읽지 않는다.

**고칠 일이 생기면 항상 조각 파일을 고치고 5 → 6 → 7을 다시 돈다.** data.json이나 HTML을 직접 고치면 다음 조립에서 사라진다. 숫자 하나·문장 하나처럼 작은 수정은 메인이 조각 파일을 직접 고친다. 다시 조사해야 하는 수정(증권사를 바꾸거나 부문 숫자를 새로 찾는 일)은 그 조각을 맡을 에이전트를 새로 띄운다.

## Step 0. 준비

- **작업 폴더**: 지금 작업 중인 폴더(cwd)에서 모든 명령을 실행한다. 결과는 `./output/`에 쌓인다. 조각 폴더는 `./output/<종목명>_<label>_parts/`(label은 Step 2의 `label`, 예: `카카오_2Q26_parts`)로 만들고, 서브에이전트에게는 **절대 경로**로 넘긴다(서브에이전트의 작업 폴더는 다를 수 있다).
- **API 키**: 없다는 오류가 나면 `~/.claude/skills/dart/.env`에 `DART_API_KEY=발급받은_키` 한 줄을 넣도록 안내하고 멈춘다(키는 opendart.fss.or.kr에서 무료). 플러그인으로 설치했어도 이 위치를 본다.

## Step 1. 종목 확정

```bash
python3 ~/.claude/skills/dart/assets/corp_registry.py "<사용자가 쓴 이름 그대로>" --verify
```

이름 부분일치로 직접 찾지 않는다("현대차"가 현대차증권으로 빠진다). 약칭·옛 이름·오타·대화체는 레지스트리가 처리한다. 종료코드 2(물어야 함)·3(없음)은 오류가 아니라 정상 분기다. 출력 JSON의 `status`로 판단한다.

- `status: "ok"`이고 `agent`가 비어 있으면 `corp.corp_code`로 다음 단계로 간다. `notes`가 있으면 사용자에게 한 줄씩 전한다.
- 그 밖의 경우(`confirm`·`ambiguous`·`not_found`, `agent`에 지시가 있음, `live_check.ok`가 false, 리츠·스팩·코넥스·결산월 비12월)는 **`references/corp-lookup.md`를 열고** 그대로 따른다. 사용자가 후보를 고르면 고른 종목코드로 이 명령을 한 번 더 실행한다.

## Step 2. 기간 정하기

먼저 `period`를 돌린다. 가장 최근에 제출된 정기보고서를 알려 준다.

```bash
python3 ~/.claude/skills/dart/assets/assemble_report.py period --corp-code <corp_code>
# → {"label": "2Q26", "report_nm": "반기보고서 (2026.06)", "args": "--year 2026 --reprt 11012", ...}
```

**사용자가 분기를 말하지 않았으면** 출력의 `args`를 다음 단계들에 그대로 붙인다. 결산월이 12월이 아니거나 코넥스면 `--fiscal-month`·`--scope annual`도 이미 들어 있다. 날짜로 분기를 짐작하지 않는다.

**사용자가 분기를 말했으면** `period`에 `--quarter`를 붙여 그 분기의 `args`를 받는다. 연도와 결산월 계산(3월 결산의 3분기는 12월 보고서)을 스크립트가 한다.

| 사용자 표현 | 덧붙일 것 |
|---|---|
| 1분기·2분기(반기)·3분기·4분기 | `--quarter 1`~`4` (4Q 단독은 스크립트가 연간 − 3Q 누적으로 계산) |
| 연간, 사업보고서, FY | `--quarter FY` (`--scope annual`이 args에 들어간다) |
| 연도까지 말함 ("2025년 3분기") | 위에 더해 `--fiscal-year 2025` (회계연도가 시작한 해. 12월 결산은 그 해 그대로) |

연도를 말하지 않았으면 그 분기 가운데 가장 최근 것이 나온다. 코넥스는 분기·반기보고서가 없어 `note`와 함께 연간 `args`가 나오니 그렇게 알린다. 지정한 분기 보고서가 아직 없으면 Step 3이 알려 준다.

사용자에게 기간을 한 줄로 알린다(위 표). 최근 분기 보고서가 아직 제출 전이라 직전 분기로 만들면 그렇게 밝힌다("3분기 보고서는 아직 제출 전이라 2Q26 기준입니다").

## Step 3. 사실 뽑기

```bash
python3 ~/.claude/skills/dart/assets/assemble_report.py facts --corp-code <corp_code> <args> \
    --parts output/<종목명>_<label>_parts
```

매출·영업이익·순이익(전년 동기 → 당기, 증감액, 증가율, 이익률), 순이익 구성(세전·법인세·계속영업·중단영업·지배주주), 재무상태(전기말 → 당기말), 누적 현금흐름, 처음 발표한 전년 숫자와의 차이, 주가와 52주 범위를 **검증 게이트와 같은 표기**의 문장으로 준다. 이 출력을 Step 4의 에이전트들에게 그대로 넘긴다.

- 주가는 전 거래일 KRX 종가다(오늘 값은 장 마감 뒤에도 넥스트레이드 거래로 바뀐다). `_price.json`에 고정돼 build도 같은 값을 쓴다.
- 전년 동기는 이번 보고서에 실린 재작성치다. 처음 발표한 숫자와 다르면 "전년 수치 재작성" 줄이 나오고 리포트 KPI 아래에 각주로 실린다.
- "개별재무제표(OFS)로 만든다"가 찍히면 사용자에게 개별 기준이라고 알린다(build도 자동으로 같게 처리한다).
- 멈추면 이유를 사용자에게 전한다. 핵심 계정이 없으면 이 리포트는 만들 수 없다. 정기보고서가 아직 없으면 직전 분기로 할지, 잠정실적으로 할지 묻는다(잠정실적은 `references/provisional.md`).

## Step 4. 조사와 출처 검증

**한 메시지에서 A1·A2a·A2b를 `run_in_background`로 동시에 띄운다.** B와 C는 확인된 뉴스를 읽어야 원인을 쓸 수 있으니 뒤에 띄운다(아래). 프롬프트는 **`references/agent-prompts.md`의 템플릿에 값만 채워** 그대로 쓴다. 각 에이전트는 결과를 조각 폴더에 순수 JSON으로 직접 쓰고 "done"만 답한다. 메인은 결과를 옮겨 적지 않는다.

| 에이전트 | 하는 일 | 쓰는 파일 |
|---|---|---|
| **A1** | 뉴스 5건 | `A1.json` |
| **A2a** | 증권사 5곳 | `A2a.json` |
| **A2b** | 사업부문 매출 (DART 본문 표) | `A2b.json` |
| **B** | 투자자 13인 평가 (V1 뒤) | `B.json` |
| **C** | 결론 2문장, 다음에 볼 것, 강세·약세 논거 각 5개, KPI 칩 (V1·V2a·V2b 뒤) | `C.json` |

**출처 검증은 조사와 겹쳐 돌린다.** A1이 끝났다는 알림이 오면 곧바로 **V1**(A1.json 검증 → `V1.json`)을, A2a가 끝나면 **V2a**(→ `V2a.json`)를, A2b가 끝나면 **V2b**(→ `V2b.json`)를 띄운다(같은 템플릿 문서). **V1이 끝나면 B를, V1·V2a·V2b가 모두 끝나면 C를 띄운다**(C가 확인된 부문·증권사 숫자를 쓴다). 그 밖에는 서로 기다리지 않는다. V1을 다시 띄워도 실패하면 B·C 프롬프트의 확인된 뉴스 자리에 "확인된 뉴스 없음"을 넣고 띄운다. 검증 에이전트가 고친 값은 `patch`에 들어가고 조립 스크립트가 반영하니, 메인이 다시 고치지 않는다.

조립 전에 두 가지를 확인한다.

- **`unverified`가 남았으면** 게이트를 통과하지 못하니 미리 처리한다. 뉴스는 그 기사를 A1.json에서 뺀다(확인된 다른 기사로 바꿀 수 있으면 바꾼다). 증권사는 빼거나 `note`에 "(미확인)"을 붙인다. 부문은 `src: "calc"`, `est: true`로 바꾼다(그 숫자는 서술에 쓸 수 없다).
- **에이전트가 실패했으면**(파일이 없거나 JSON이 깨짐) 오류를 덧붙여 같은 템플릿으로 한 번 다시 띄운다. 건수가 모자랄 때의 기준은 `references/troubleshooting.md` "조사 단계". 증권사 0곳은 실패가 아니다(커버리지 없는 회사).

서브에이전트를 쓸 수 없는 환경이면 메인이 같은 템플릿대로 파일을 차례로 만든다. 웹 검색만은 한 메시지에 몰아 병렬로 보낸다.

## Step 5. data.json 조립

A1·A2a·A2b·B·C·V1·V2a·V2b 파일이 모두 생기면 조립한다(첫 조립에는 R.json이 없다는 안내가 나온다. 정상이다):

```bash
python3 ~/.claude/skills/dart/assets/assemble_report.py build --corp-code <corp_code> <args> \
    --parts output/<종목명>_<label>_parts -o output/<종목명>_<label>_data.json
# 순이익을 지배주주순이익으로 보이려면 facts·build 모두에 --np-basis parent (기본은 연결 당기순이익)
```

스크립트가 meta의 모든 숫자와 라벨(결산월이 12월이 아니면 실제 달력 기간까지), 성장 기여도, 목표가 범위, 컨센 비율을 계산하고 검증 장부를 합친다. 부문 합계·투자자 13인·목표가 누락이 어긋나면 이유를 찍고 멈춘다. 그때는 위의 수정 원칙대로 조각을 고치고 다시 조립한다.

**전문가 평가.** 조립된 data.json으로 에이전트 **R**을 띄운다(`references/agent-prompts.md`의 R 템플릿, `{DATA}`에 data.json 절대 경로). RED(논리)·SILVER(분야 전문가)·GOLD(실제 독자)가 10점 만점으로 평가해 `R.json`에 쓰고, 같은 명령으로 **다시 조립**하면 리포트 맨 아래에 실린다. 평가가 없거나 형식이 틀리면 게이트가 FAIL을 낸다.

**9.5 미만이면 한 번 고친다.** 한 역할이라도 9.5 미만이고 `target`이 B·C인 fix가 있으면(모두 none이면 고침 없이 Step 6), `R.json`·`B.json`·`C.json`을 `R_v1.json`·`B_v1.json`·`C_v1.json`으로 복사해 두고, `target`이 C인 fix를 모아 C를, B인 fix를 모아 B를 같은 템플릿에 "전문가 평가의 지적: <fix 그대로>"를 덧붙여 다시 띄운다(둘 다면 둘 다). `target`이 none인 fix는 고치지 않는다. 리포트에 `limit`(남은 한계)으로 실린다. 한 문장짜리 논리 오류는 메인이 조각을 직접 고쳐도 된다. 조립한 뒤 R을 한 번 더 띄워 다시 조립한다. 이 고침은 한 번만 한다. 그래도 9.5 미만이면 그대로 진행하고 전달할 때 최저점과 남은 한계를 알린다. 평가 뒤에 본문 조각을 또 고치면 조립 스크립트가 경고하고 리포트에 "이 평가 뒤에 본문 일부가 고쳐졌다"가 붙는다.

## Step 6. 숫자 검증 게이트

```bash
python3 ~/.claude/skills/dart/assets/verify_report.py output/<종목명>_<label>_data.json
```

세 층을 대조하고, 하나라도 틀리면 FAIL이다.

| 층 | 보는 것 | 정답 |
|---|---|---|
| A 산술 | 증감률·이익률·합계·성장 기여도·컨센 비율·상승 여력 | 다시 계산한 값 |
| B 원천 | 종목명·종목코드·corp_code가 지금 상장된 한 회사인지, 매출·영업이익·순이익, 기간 라벨, 종가·52주 | 상장사 목록, DART 재조회, KRX 일봉 |
| C 출처 | 뉴스·증권사·부문의 검증 기록, 서술 속 단위가 붙은 숫자: 범위 "A ~ B원"의 앞 숫자, 같은 마디의 계정 이름(매출·영업이익·법인세·자본 등)과 맞는지, 부호와 늘었다·줄었다가 원천과 같은지 | A·B에서 나온 값. 추정 부문(est)은 근거가 되지 못한다. 확인된 기사·증권사 note의 숫자는 출처를 같은 문장에 밝힐 때만, 처음 발표 기준 증가율은 그렇다고 밝힐 때만 통과한다. 기사 숫자를 꼭 써야 하면 원문을 확인해 `V1.json`의 `claims`에 `{"text": 본문 표기 그대로, "url", "status": "confirmed"}` |

| 결과 | 코드 | 행동 |
|---|:---:|---|
| PASS | 0 | Step 7로 |
| FAIL | 1 | 찍힌 항목을 **한 번에 모두** 조각에서 고치고 → Step 5 조립 → 다시 검증 |
| BLOCKED | 2 | 멈추고 사용자에게 묻는다(아래) |
| INCOMPLETE | 3 | 네트워크 장애. 회차를 쓰지 않았다. 한 번 더, 또 실패하면 사용자에게 |

- 회차는 최대 3번이다(data.json 내용이 바뀐 채 실행할 때만 1회 쓴다). 그래서 하나 고치고 돌리기를 반복하지 않는다.
- 정답은 원천(DART·KRX·원문)이다. 확인할 수 없는 숫자는 지어내지 말고 문장에서 뺀다.
- **BLOCKED**면 `<data>.verify.md`의 남은 불일치를 보여 주고 고르게 한다(말은 위 표). ①을 고르면 조각에 반영하고 다시 조립 → `verify_report.py <data> --reset`(회차만 지운다) → 다시 검증. ②는 `build_report.py <data> --allow-unverified`. 두 플래그는 사용자가 그 선택지를 골랐을 때만 쓴다.

## Step 7. 빌드·전달

```bash
python3 ~/.claude/skills/dart/assets/build_report.py output/<종목명>_<label>_data.json
```

게이트가 PASS이고 그 뒤 data.json이 바뀌지 않았을 때만 `output/<종목명>_<YYYYMMDD>_<NN>.html`을 만들고(아니면 종료코드 2로 멈춘다. Step 6부터 다시), 헤더에 "숫자 검증 통과"를 찍는다. 위 "사용자에게 하는 말"의 전달 형식으로 알리고, 할 수 있으면 열어서 보여 준다. 사용자가 PDF를 원하면 `references/pdf.md`.
