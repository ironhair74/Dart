# 문제가 생기면

SKILL.md의 단계가 멈췄는데 그 단계 설명으로 풀리지 않을 때 연다. 고치는 방법은 SKILL.md의 수정 원칙(조각을 고치고 5 → 6 → 7)을 따른다. 잠정실적 경로의 문제는 `references/provisional.md`에 있다.

## 시작 전

| 증상 | 원인 | 해결 |
|---|---|---|
| 종목을 못 찾음 (신규 상장·사명 변경) | 목록이 오래됨 | `corp_registry.py --refresh` 뒤 다시 찾는다 |
| status 020 · "일일 호출 한도" | DART 일일 한도(2만 건) 초과. `DartClient`가 이미 두 번 더 시도한 결과 | 내일 다시 하거나 다른 키 |
| status 800 · "DART에 접속하지 못했다" | DART 점검 또는 네트워크 | 잠시 뒤 다시 |

## 조사 단계

| 증상 | 원인 | 해결 |
|---|---|---|
| 다시 띄워도 뉴스가 5건이 안 됨 | 기사가 적은 회사 | 3건 이상이면 진행하고 사용자에게 건수를 알린다. 그보다 적으면 알리고 진행할지 묻는다 |
| 증권사가 5곳보다 적거나 0곳 | 커버리지 없는 중소형주 | 실패가 아니다. 다시 띄우지 않고 진행하며 사용자에게 한 줄로 알린다 |
| B·C가 "원인 확인 필요"를 씀 | V1보다 먼저 띄웠거나, 원인이 facts·확인된 뉴스 어디에도 없음 | V1 뒤에 띄웠는지 본다. 원인이 facts "순이익 구성"에 있으면 그 줄을 짚어 다시 띄운다 |

## facts · build 단계

| 증상 | 원인 | 해결 |
|---|---|---|
| facts: "재무제표를 받지 못했다" | 그 분기 정기보고서 미제출 | `period`로 직전 분기로 만들거나, 사용자가 원하면 `references/provisional.md` |
| facts: "재무제표를 USD로 공시한다" | 국내 상장 외국 기업(코오롱티슈진 등 950xxx) | 원화 기준 리포트라 만들 수 없다. 사용자에게 알리고 중단 |
| build: "SEGS 합계가 총매출과 다르다" | 부문 숫자가 총매출과 부문 수(억)보다 크게 어긋남. 그보다 작은 차이는 스크립트가 `연결조정` 행으로 자동으로 맞춘다 | 빠진 부문이 있는지 본다. 부문 숫자를 새로 찾아야 하면 같은 템플릿으로 A2b를 새로 띄운다 |
| build: "C.json에 HEADLINE이 없다" | 옛 템플릿으로 C를 띄움 | 지금 C 템플릿으로 C를 다시 띄운다 |
| build: "R.json이 본문 조각보다 오래됐다" | R 평가 뒤에 B·C 등을 고침 | Step 5의 고침 한 번이면 R을 다시 띄운다. 그 뒤의 작은 수정이면 그대로 두어도 된다(리포트에 표시된다) |
| build: "PERSONAS가 13인이 아니다" | B 출력 | 같은 템플릿으로 B를 새로 띄운다(빠진 인물만 메인이 쓰지 않는다. 판단 규칙 적용이 B의 일이다) |
| build: "증권사 목표가가 없다" | A2a에 tp 없는 항목 | 메인이 그 항목을 A2a.json에서 뺀다 |
| build: "meta 키가 다르다" | data.example.json 계약이 바뀜 | 조립 스크립트와 예시를 맞춘다(스킬 유지보수 사항) |
| 게이트 "지배주주순이익과 일치" 힌트 | 순이익 기준이 다름 | 지배주주 기준이 의도라면 facts·build에 `--np-basis parent`를 붙여 다시 조립 |

## 숫자 검증 게이트

| 증상 | 원인 | 해결 |
|---|---|---|
| A층 산술 불일치 | 조각 숫자 오타, 부문 합계 | 해당 조각을 고치고 다시 조립 |
| B층 "식별" 불일치 | 다른 회사의 corp_code·종목코드 | Step 1을 다시 돌려 corp_code를 확인하고 처음부터 |
| C층 "데이터에서 나오지 않는 숫자" | B·C 문장이나 부문 설명(sub)에 facts에 없는 숫자, 또는 파생 숫자(차이·비율) | 조각에서 숫자를 빼거나 facts 표기로 바꾸고 다시 조립. 기사·공시 숫자를 꼭 써야 하면 원문을 확인해 `V1.json`·`V2a.json`·`V2b.json`의 `claims`에 `{text, url, status}` |
| C층 "계정 값이 아니다" · "부호가 원천과 반대다" | 같은 마디의 계정 이름(매출·영업이익·법인세 등) 뒤에 다른 계정 숫자를 썼거나, 늘었다·줄었다(또는 +/−)가 원천과 반대 | 숫자를 그 계정의 facts 표기로 바꾸거나 방향을 바로잡는다. 그 숫자가 속한 계정 이름을 숫자 바로 앞에 둔다 |
| C층 "출처(매체·증권사)를 밝힌다" · "처음 발표한 전년 대비" | 확인된 기사·증권사 note의 숫자를 출처 없이 썼거나, 처음 발표 기준 증가율을 성장률처럼 썼다 | 같은 문장에 "(한국투자증권 추정)"처럼 출처를 붙이거나, "처음 발표한 전년과 견주면"으로 밝힌다 |
| C층 "앞뒤가 바뀌었다" · "직전 분기 대비 값" | "A에서 B로"의 비교·당기 순서가 원천과 반대이거나, 직전 분기 대비 증가율을 전년 대비로(또는 반대로) 썼다 | facts의 "전년 → 당기", "직전 분기 대비" 줄 표기 그대로 쓴다 |
| V2b가 DART 공시 부문 숫자를 `unverified`로 | dart.fss.or.kr 뷰어는 WebFetch에 목차만 보인다 | V2b 템플릿대로 `dart_text.py <rcpNo> "영업부문"`으로 본문 표를 읽게 한다(단위 천원·백만원을 억원으로 바꿔 비교) |
| C층 출처 기록 없음 | V1·V2a·V2b가 없거나 `unverified` | 검증 에이전트를 다시 돌리거나, 확인 못 한 항목을 조각에서 뺀다(부문은 `est: true`) |

## 빠른 조회 (DART 도구 16개, `mcp_server.py`)

| 증상 | 원인 | 해결 |
|---|---|---|
| `note`: "데이터가 없습니다 (status 013)" | 그 기간 보고서에 그 항목이 없다. 재무 지표는 2023년 3분기 이전이 없고, 1분기 보고서에는 직원 급여가 빠진 회사가 많다 | 기간을 바꿔 한 번 더 보거나, 없다고 그대로 알린다 |
| `fin_statements`에 IS가 없고 CIS가 왔다 | 손익을 포괄손익계산서 한 장으로 공시한 회사(소형사에 흔하다) | 정상. `meta.statement_note`에 적혀 있다 |
| `filing_search`가 "기간을 3개월 안으로" | `corp` 없이 시장 전체를 찾을 때의 DART 제한 | `from`·`to`를 좁히거나 `corp`를 준다 |
| MCP로 연결했는데 도구가 안 보인다 | 앱이 `python3`를 못 찾거나 경로가 틀렸다 | Claude Desktop은 `~`를 풀지 않는다. 설정에 전체 경로를 쓰고, `python3` 대신 `which python3`가 알려 주는 전체 경로를 쓴다. 터미널에서 `mcp_server.py --list`가 도는지 먼저 본다 |
| 모든 도구가 "DART_API_KEY가 없습니다" | 플러그인 설치본(`~/.claude/plugins/cache/…`)이나 다른 폴더에서 서버가 떠서 `.env`를 못 본다 | 키를 `~/.claude/skills/dart/.env`에 둔다. 이 위치는 어디서 띄워도, 플러그인으로 깔아도 찾는다 |

`requests`가 없는 파이썬에서도 돈다(`http_compat.py`가 표준 라이브러리로 접속한다).
