# 가드레일 (하지 않는 것)

스크립트가 막는 것(✔ 자동)과 모델이 지켜야 하는 것(✎ 규칙)을 나눠 적는다.

## 데이터
- ✎ 파일 없이 수치를 만들지 않는다. 기억 속 대학 통계를 쓰지 않는다.
- ✔ 분교는 기본 제외(`--include-branch`로만 포함). 합계·평균 행은 버린다. — `load.py`
- ✔ 같은 학교·연도·지표에 서로 다른 값이 있으면 `conflicts`로 보고한다. — `load.py`
- ✔ 상식 범위 밖 값(예: 취업률 130%)은 경고·검증 실패. 열 매핑 오류일 가능성이 크다. — `analyze.py`, `verify.py`
- ✎ 가상 샘플(`sample_data/`) 결과를 실제 대학 분석처럼 내보내지 않는다.

## 숫자
- ✔ 해석 문장 속 숫자는 `analysis.json`(또는 원자료) 근거가 있어야 한다. — `verify.py`
- ✎ 모델이 직접 평균·비율을 계산하지 않는다. 필요하면 `analyze.py`에 계산을 넣는다.
- ✎ %와 %p를 구분한다(비율의 차이는 %p).

## 표현
- ✔ 금지어: 부실대학, 퇴출, 폐교 확정/폐교될, 공식 기준, 확정적으로, 반드시 탈락 등. — `verify.py`의 `BANNED`
- ✎ '내부 경보선'을 정부 평가(대학기본역량진단, 재정지원 제한 등) 기준처럼 말하지 않는다.
- ✎ 원인을 단정하지 않는다. 공시 자료로 알 수 없는 원인은 "가능성"으로만.
- ✎ 특정 대학을 깎아내리거나 순위 줄 세우기만 하는 결론을 피한다. 개선 여지와 함께 쓴다.

## 실행
- ✎ 검증 실패를 숨기지 않는다. 3회 고쳐도 실패하면 남은 오류를 그대로 보고한다.
- ✎ 사용자 파일을 고치거나 지우지 않는다. 산출물은 `workspace/`에만 쓴다.
- ✎ 외부로 데이터를 보내지 않는다(리포트 공유·게시는 사용자가 결정).
